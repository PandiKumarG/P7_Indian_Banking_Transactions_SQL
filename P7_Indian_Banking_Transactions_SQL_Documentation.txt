PROJECT 7 – INDIAN BANKING TRANSACTIONS ANALYSIS USING SQL

1. PROJECT OVERVIEW

This project analyzes Indian banking transaction records using
PostgreSQL. The analysis focuses on transaction performance, high-value
debit transactions, regional transaction activity, and the loan
portfolio.

2. DATASET OVERVIEW

Dataset: Indian Banking Transactions 2019–2024 Database: PostgreSQL 
Main table: project_7_indian_banking_transactions

The dataset contains 550,000 transaction records and 18 columns.

Columns: 
1. transaction_id 
2. customer_id 
3. transaction_date 
4.transaction_time 
5. account_type 
6. transaction_type 
7.transaction_amount 
8. transaction_direction 
9. balance 
10.merchant_category 
11. state 
12. credit_score 
13. has_loan 
14. loan_type
15. emi_amount 
16. transaction_status 
17. channel 
18. kyc_status

Key dataset observations: 
- transaction_id is unique. 
- The dataset covers 2019 to 2024. 
- There are approximately 79,916 distinct customers. 
- transaction_direction contains Credit and Debit. 
- transaction_status contains Success, Failed, Pending, and Reversed. 
- has_loan uses 1 for customers with a loan and 0 for customers without a loan. 
- loan_type contains loan categories and missing values. - The loan analysis excludes records where loan_type is NULL.

3. PROJECT ANALYSIS

Q1. Transaction Channel and Type Performance Analysis

Business requirement: Evaluate the operational reliability of different
transaction channels and transaction types by identifying combinations
with higher transaction failure rates.

Output columns: 
- channel 
- transaction_type 
- total_transactions
- successful_transactions 
- failed_transactions 
- pending_transactions 
- reversed_transactions 
- failure_percentage

Approach: 
- Group records by channel and transaction_type. 
- Count all transactions and count transactions by each status using conditional aggregation. 
- Calculate failure percentage as failed transactions divided by total transactions, multiplied by 100. - Sort by failure
percentage in descending order.

SQL concepts used: - Common Table Expression (CTE) - GROUP BY - COUNT -
Conditional aggregation - CASE WHEN - CAST - ROUND - ORDER BY

Q2. Identifying High-Value Debit Transactions Across States

Business requirement: Identify the top five distinct transaction amount
ranks for successful debit transactions within each state.

Output columns: - state - transaction_id - customer_id -
transaction_date - transaction_type - channel - transaction_amount -
transaction_rank

Approach: 
- Filter for Debit transactions with Success status. 
- Apply DENSE_RANK() separately within each state, ordering transaction_amount from highest to lowest. 
- Retain rows with transaction_rank less than or equal to 5. 
- Sort by state and transaction rank.

SQL concepts used: 
- Window function: 
DENSE_RANK() 
- PARTITION BY
- ORDER BY 
- WHERE 
- Common Table Expressions (CTEs)

Q3. Regional Transaction Activity Analysis

Business requirement: Analyze monthly transaction activity by Indian
region to understand regional differences in transaction volume and
transaction value.

Supporting table: state_region_mapping

Supporting table columns: 
- state 
- region

The supporting table maps each state in the transaction dataset to a
geographical region. It is joined to the main transaction table using
the state column.

Output columns: 
- region 
- transaction_month 
- total_transactions
- total_transaction_amount 
- credit_transactions 
- debit_transactions
- total_credit_amount 
- total_debit_amount

Approach: 
- Join the main transaction table with state_region_mapping using an INNER JOIN. 
- Convert transaction_date to a date using TO_DATE with the MM/DD/YYYY format, then use DATE_TRUNC(‘month’, …) to derive the calendar month. 
- Group the results by region and transaction month. 
- Count total, credit, and debit transactions. 
- Sum total transaction amount and separately sum credit and debit amounts. 
- Sort by region and transaction month in ascending order.

SQL concepts used: 
- INNER JOIN 
- GROUP BY 
- COUNT 
- SUM 
- DATE_TRUNC
- TO_DATE 
- SUBSTRING and CAST for formatting the month 
- Conditional aggregation 
- CASE WHEN - ORDER BY

Q4(a). Identifying Above-Average Loan Types

Business requirement: Identify loan types whose total EMI obligation is
greater than the average of the loan-type-wise total EMI obligations.

Calculation sequence: 
1. Calculate the total EMI amount separately for each loan type. 
2. Calculate the average of those loan-type-wise total EMI amounts. 
3. Return loan types whose total EMI is greater than that average.

Output columns: 
- loan_type 
- total_borrowers 
- total_emi

Approach: 
- Consider records where has_loan = 1. 
- Exclude records with NULL loan_type. 
- Group records by loan_type. 
- Count distinct customers and calculate total EMI for each loan type. 
- Use a nested subquery to calculate the average of the grouped total EMI values. 
- Use HAVING to retain loan types whose total EMI exceeds that average.

SQL concepts used: 
- Subqueries, including a nested derived table
- GROUP BY 
- COUNT(DISTINCT …)
- SUM 
- AVG 
- HAVING 
- ORDER BY

Q4(b). Classifying Borrowers by Credit Score

Business requirement: Classify borrowers with loans into credit-score
categories and count the distinct borrowers in each category.

Output columns: - credit_score_category - total_borrowers

Credit-score categories:
- High: credit score 750 or above. 
- Medium: credit score from 650 to 749. 
- Low: credit score below 650.

Approach: 
- Consider records where has_loan = 1. 
- Use CASE WHEN to assign each borrower record to a credit-score category. 
- Group by credit-score category. 
- Count distinct customers in each category.

SQL concepts used: 
- CASE WHEN 
- Common Table Expressions (CTEs) 
- GROUP BY 
- COUNT(DISTINCT …) 
- ORDER BY
